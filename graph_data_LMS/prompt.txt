# MASTER PROMPT: Build an Advanced Local Data Analytics Learning & Testing Lab in Python

## 1. Your Role and Mission

Act as a senior Python software engineer, data scientist, analytics consultant, instructional designer, assessment specialist, and UX/UI designer.

Design and implement a complete, production-quality **Data Analytics Learning & Testing Lab** that runs locally on a computer through a web browser.

The application must function as an interactive learning platform in which users can study data analytics, practise real analytical tasks, write and execute code, receive immediate feedback, assess their progress, and demonstrate measurable improvements in their analytical competence.

Do not create a static educational website or a collection of tutorials. Build a practical learning environment where users learn by doing.

The application must be beginner-friendly while supporting advanced learners who want to develop professional-level analytics skills.

**Primary objective:** By completing the curriculum, users should be significantly more competent at solving real business problems using data, choosing appropriate analytical methods, writing correct code, interpreting results, and communicating insights to stakeholders.

## 2. Technology Stack and Local Execution

Use the following technology stack unless a genuine technical limitation requires a justified alternative:

- **Programming language:** Python 3.11 or newer.
- **Application framework:** Streamlit.
- **Data manipulation:** pandas and NumPy.
- **SQL execution:** DuckDB and/or SQLite.
- **Statistical analysis:** SciPy and statsmodels.
- **Machine learning:** scikit-learn.
- **Data visualization:** Matplotlib and Plotly.
- **Excel file handling:** openpyxl and pandas.
- **User progress and results:** SQLite.
- **R support:** Optional local R execution through an installed R interpreter.
- **Testing:** pytest.
- **Configuration:** requirements.txt and a documented setup procedure.

The application must run on the user's computer, accessible through a local address such as `http://localhost:8501`.

Avoid mandatory cloud services, paid APIs, subscriptions, authentication providers, or external databases. Core lessons, datasets, quizzes, progress tracking, and Python/SQL exercises must work offline after installation.

Check installed dependencies and available software capabilities at startup. If R is not installed, display clear installation instructions and let users continue with the remaining modules.

Do not claim to execute Power BI, Tableau, Excel, or Looker Studio natively inside the application. Instead, provide simulated exercises, tool-specific practical assignments, downloadable datasets, solution guides, and instructions for completing selected tasks in the actual software.

## 4. Five Core Learning Modules

### Module 1: Descriptive Analytics

**Core question:** What happened, what is happening, and how can we summarize business performance?

**Primary tools:** SQL, Microsoft Excel, and Power BI.

Create a structured curriculum covering:

**SQL**
- SELECT, DISTINCT, WHERE, ORDER BY, and LIMIT.
- COUNT, SUM, AVG, MIN, and MAX.
- GROUP BY and HAVING.
- CASE expressions.
- NULL handling.
- INNER, LEFT, RIGHT where supported, and FULL JOIN concepts.
- Common table expressions.
- Subqueries.
- Date and text functions.
- Window functions.
- Ranking, running totals, and period comparisons.
- KPI calculations and business reporting.
- Query readability and performance fundamentals.

**Excel**
- Formulas and cell references.
- Relative and absolute references.
- IF, IFS, SUMIF, SUMIFS, COUNTIF, COUNTIFS, and lookup functions.
- XLOOKUP and equivalent approaches.
- Text and date functions.
- Data cleaning and validation.
- Sorting, filtering, conditional formatting, and tables.
- PivotTables and PivotCharts.
- KPI calculations.
- What-if analysis and scenario tables.
- Building an analytical spreadsheet that another person can audit.

**Power BI**
- Data import and transformation concepts.
- Data modeling and relationships.
- Star schemas and fact/dimension tables.
- Power Query fundamentals.
- Basic DAX measures and calculated columns.
- Measures for revenue, profit, growth, and year-to-date metrics.
- Slicers, filters, drill-downs, and cross-filtering.
- Dashboard layout and KPI reporting.
- Data refresh and basic performance principles.

Power BI assignments must include realistic tasks that can be completed in Power BI Desktop, with clear instructions and expected outputs. Where native software is unavailable, provide an equivalent simulation inside the app.

**Practical project:** Analyze a fictional retail company's sales, products, regions, customers, costs, and margins. Produce a KPI report, SQL-based summaries, an Excel analysis workbook, and a Power BI dashboard specification.

The learner must explain the business implications of the results, not merely calculate the numbers.

### Module 2: Diagnostic Analytics

**Core question:** Why did something happen, and what evidence supports the explanation?

**Primary tools:** Python, R, and SQL.

Cover:

- Data quality checks and exploratory data analysis.
- Missing values, duplicates, outliers, and inconsistent records.
- Segmentation and subgroup comparisons.
- Root-cause analysis.
- Funnel analysis and customer journey investigation.
- Cohort and retention analysis.
- Correlation and covariance.
- Confounding variables and Simpson's paradox.
- Hypothesis testing and p-values.
- Confidence intervals and practical significance.
- A/B testing fundamentals.
- Statistical assumptions and their limitations.
- Anomaly detection.
- Interpreting results without confusing correlation with causation.
- Communicating evidence, limitations, and alternative explanations.

**Python practice:** pandas, NumPy, Matplotlib, SciPy, and statsmodels.

**R practice:** vectors, data frames, dplyr, ggplot2, grouping, summary statistics, visual exploration, and basic statistical testing.

**SQL practice:** joining multiple tables, comparing segments, cohort queries, window functions, and tracing changes in business KPIs.

**Practical project:** Investigate why customer retention has fallen. Compare customer segments, acquisition channels, product categories, and customer cohorts. Require the learner to distinguish supported conclusions from hypotheses that need further investigation.

### Module 3: Predictive Analytics

**Core question:** What is likely to happen next, and how reliable is that prediction?

**Primary tools:** Python and R.

Cover:

- Prediction versus inference.
- Defining prediction targets.
- Regression and classification.
- Exploratory analysis for modeling.
- Feature engineering.
- Train, validation, and test splits.
- Data leakage and temporal leakage.
- Baseline models.
- Linear and logistic regression.
- Decision trees and random forests.
- Model pipelines and preprocessing.
- Cross-validation.
- Hyperparameter tuning.
- Overfitting and underfitting.
- Classification thresholds.
- Class imbalance.
- Confusion matrices, precision, recall, F1, ROC-AUC, and PR-AUC.
- Regression metrics including MAE, RMSE, and R-squared.
- Time-series forecasting fundamentals.
- Model interpretation and feature importance.
- Prediction uncertainty and limitations.
- Model drift, monitoring, and responsible use.

Teach learners why the correct metric depends on the business problem.

Do not reward a model simply for achieving a high score. Require the learner to establish a baseline, avoid leakage, justify evaluation metrics, interpret errors, and assess whether the model is useful in practice.

**Practical project:** Predict customer churn or future sales using a reproducible workflow. Compare at least two approaches and justify the final model using appropriate evaluation criteria.

Provide working Python code and R equivalents where feasible. R lessons should use clearly explained packages and avoid assuming Python and R have identical syntax or behavior.

### Module 4: Prescriptive Analytics

**Core question:** What should we do, given the evidence, constraints, risks, and available resources?

**Primary tools:** Python and R.

Cover:

- Decision variables.
- Objective functions.
- Constraints and feasible solutions.
- Linear programming.
- Resource allocation.
- Capacity planning.
- Product mix optimization.
- Pricing and discount scenarios.
- Inventory and reorder decisions.
- Scheduling and assignment problems.
- Cost-benefit analysis.
- Simulation and Monte Carlo methods.
- Sensitivity analysis.
- Scenario comparison.
- Trade-offs among profit, cost, service quality, and risk.
- Translating mathematical results into actionable recommendations.

Use Python libraries such as SciPy and, where appropriate, an optional optimization library. Provide equivalent R approaches when practical.

**Practical project:** Allocate a limited marketing budget across several channels to maximize expected profit subject to budget and operational constraints. Include scenario analysis and sensitivity testing.

The learner must explain the recommended decision, the assumptions behind it, the constraints that affect it, and the conditions under which the recommendation would change.

### Module 5: Data Visualization and Communication

**Core question:** How can data be communicated clearly, accurately, and persuasively?

**Primary tools:** Tableau, Matplotlib, and Looker Studio (formerly Google Data Studio).

Also include visualization principles relevant to Power BI and Excel.

Cover:

- Selecting the right chart for the analytical question.
- Tables, bar charts, line charts, scatterplots, histograms, boxplots, heatmaps, and maps.
- Distributions, relationships, comparisons, and trends.
- Univariate, bivariate, and multivariate analysis.
- Color, contrast, hierarchy, typography, and whitespace.
- Axes, scales, labels, annotations, legends, and units.
- Accessibility and color-vision considerations.
- Dashboard design and layout.
- Interactive filters and drill-downs.
- Reducing clutter and cognitive load.
- Avoiding misleading visualizations.
- Communicating uncertainty and limitations.
- Executive summaries and data storytelling.
- Choosing charts based on audience and decision context.

**Matplotlib exercises:** Require learners to write and modify actual Python visualization code, execute it, and inspect the resulting charts.

**Tableau exercises:** Provide realistic workbook tasks, field assignments, calculated-field challenges, dashboard design requirements, and instructions for importing data and creating visualizations in Tableau.

**Looker Studio exercises:** Provide instructions for preparing and importing CSV or spreadsheet data, configuring dimensions and metrics, creating charts, applying filters, and assembling interactive reports.

**Practical project:** Build a visualization portfolio that answers five business questions using appropriate chart types. Include a dashboard critique exercise in which the learner identifies misleading elements and proposes specific improvements.

Where the native desktop or cloud product is not available, provide an interactive simulation or guided assignment rather than pretending to execute the real product.

## 5. A Unified Learning Experience

Each module must support four levels:

1. **Beginner:** Learn terminology, concepts, and fundamentals.
2. **Intermediate:** Apply methods to realistic datasets.
3. **Advanced:** Solve multi-step analytical problems.
4. **Professional:** Complete open-ended projects and defend analytical decisions.

Each lesson should follow this structure:

1. Learning objectives.
2. Short conceptual explanation.
3. Business context and real-world example.
4. Worked solution with explanations.
5. Interactive knowledge check.
6. Guided practical exercise.
7. Independent challenge.
8. Feedback and explanation.
9. Summary and key takeaways.
10. Suggested revision or next lesson.

Avoid unnecessarily long lectures. Prioritize practical work, examples, and clear explanations of why each technique is useful.

Teach the learner to think like an analyst: define the business question, inspect the data, select an appropriate method, validate the result, interpret the evidence, and communicate the recommendation.

## 6. Assessment System: Multiple Choice and Open-Ended Work

The application must support two complementary assessment types.

### A. Multiple-Choice Questions

Create a substantial question bank with questions tagged by:

- Learning module.
- Topic.
- Tool.
- Difficulty.
- Competency.
- Question type.
- Correct answer and explanation.

Each question should have four answer choices where appropriate, one best answer unless explicitly marked as multi-select, and plausible distractors based on common mistakes.

Support:

- Randomized question order.
- Randomized answer order when appropriate.
- Immediate or end-of-test feedback.
- Explanations of why the correct answer is right.
- Explanations of why the distractors are wrong.
- Topic-specific results.
- Question review.
- Retry with a new set of questions.
- Timed tests as an optional setting.
- Exam mode with feedback withheld until submission.

Do not use trivial questions exclusively. Test the learner's ability to interpret results, identify analytical errors, select appropriate methods, recognize limitations, and make decisions.

### B. Open-Ended Coding Challenges

Provide a coding editor or suitable multiline code input for practical programming tasks.

Required capabilities:

- Write code from scratch.
- Edit starter code.
- Execute supported exercises.
- View results, error messages, and relevant output.
- Submit solutions.
- Receive automated feedback.
- Reveal hints progressively.
- Compare submitted code with a worked solution after an attempt.
- Retry challenges.
- Track attempts and improvement.

Support Python and SQL code execution directly. Support R execution when the local R runtime is available.

For each coding exercise, provide:

- A business question.
- A dataset and schema.
- Clear requirements.
- Expected output structure.
- Sample input and output where helpful.
- Hidden or visible automated test cases.
- A scoring rubric.
- Hints and progressive assistance.
- A reference solution with an explanation.

Evaluate solutions using appropriate checks, not simple string matching. For example, SQL answers should be assessed against the returned dataset, while Python answers should be evaluated using assertions, output checks, and task-specific criteria.

Where multiple valid approaches exist, allow equivalent solutions.

Feedback should identify the specific error, explain why it matters, and suggest the next step rather than merely displaying “Wrong answer.”

**Execution safety:** Run submitted code outside the main Streamlit process, impose execution timeouts, use temporary working directories, and avoid exposing secrets or sensitive files. Provide an optional Docker-based execution environment for stronger isolation. Do not describe a basic subprocess or restricted `exec()` implementation as a secure sandbox against malicious code. Make the local, single-user trust assumptions explicit.

### C. Business Case Assessments

In addition to quizzes and code execution, create scenario-based tasks such as:

- Explain a sudden decline in revenue.
- Determine why customer churn increased.
- Select and evaluate a predictive model.
- Recommend a budget allocation.
- Critique a misleading chart.
- Recommend KPIs for a management dashboard.

Assess answers using transparent rubrics that consider methodological correctness, evidence, reasoning, communication, and business relevance.

For free-text answers, use transparent rubric-based scoring or self-assessment when no external grading service is configured. Never claim that subjective free-text responses are objectively graded unless a suitable evaluation method is actually implemented.
